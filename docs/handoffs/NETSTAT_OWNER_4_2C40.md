# v4.2c40 — TCP owner read fallback

Observed on Windows: TCP connect succeeds to 8790/8791/8502/8852/8702/8712 while Get-NetTCPConnection sometimes emits zero Listen records. The Caddy process exists but status is unverified. On zero Listen results only, Port-Owned tries a second independent Windows netstat snapshot and accepts **one and only one** IPv4 127.0.0.1:<port> LISTENING row with the exact recorded process PID. Any mismatch, PID 0, multiple rows, missing output, non-listening status or command error fails closed. The caller continues checking executable/config command line. No process changes, no adoption, no PROD changes. This cannot fix a case where netstat also returns no listener; it adds diagnostics confidence and may restore ownership where netstat is reliable. Windows runtime test required; tests static only. Do not bypass START safeguards.
