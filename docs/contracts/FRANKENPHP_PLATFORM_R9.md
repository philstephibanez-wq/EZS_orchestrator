- Le service Windows EZS_FrankenPHP (WinSW) héberge ROOT, EZScore DEV, EZStudio LAB et Assistant dans un seul processus FrankenPHP. PROD reste hors pilote, sans modification de 8501/8510/8511. Tout ancien instance sur 8502/8602/8701/8702/8712/8713 doit être arrêtée hors du script de cutover, en respectant son travail en cours.
- Le résident et l'ancien watchdog ROOT deviennent de purs observateurs. Le bootstrap individuel est désactivé ; la collecte hard TCP/HTTP est conservée dans le JSON/Twig.
- DEV dispose d'une bascule de routage sous forme de marqueur de fichier `runtime/web-modes/dev.maintenance`. Le Caddyfile teste l'existence de ce marqueur à chaque requête, sert HTML de maintenance 503 depuis le frontal 8502 avec Retry-After, sans arrêt du serveur. Le retour en mode Normal supprime le marqueur. Aucun effet sur PROD.
- Le nouveau `Caddyfile.platform.r9` s'appuie sur `php_server { env APP_ENV dev }`, supporté par FrankenPHP. Aucun FastCGI. Les anciens Caddyfiles DEV/PROD sont conservés comme références SSO/médias. Si la page ne fonctionne pas, rollback service.
- Le service installé sur MAIN est ROOT only et Auto selon Windows, XML historique Manual : la recette du pilote doit valider les deux états séparément. `Apply` n'arrête ni ne démarre un processus ; `cutover.ps1 -Action Cutover` est une opération explicite avec sauvegarde et rollback. Il **refuse les ports étrangers déjà écoutés**, le mode PROD initial n'est pas modifié, et le rollback ne tue jamais de PID arbitraire.
