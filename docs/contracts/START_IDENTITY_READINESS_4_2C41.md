# v4.2c41 — START identity vs readiness

Audit reference: v2.4b validated 2026-10-28 with live processes. After reboot, PID state and unreliable Windows TCP snapshot blocked progress. In **non-destructive START only**, preserve the saved running Caddy when PID, binary and command signature match, without gating on all five listeners. Similarly preserve already-running root PHP when PID, executable and `-b` signature match. No adoption of an unknown PID, no second Caddy. If old Caddy is genuinely absent, discard state only if saved PHP PID is absent and all six facade/root ports are both unlisted **and TCP-unreachable**. If old PHP is missing but its port is reachable, refuse instead of starting another listener. STOP and repair guards unchanged. START then moves to DEV/LAB/Assistant readiness validation; HTTP 502 remains an error, never success. PROD entirely unchanged. Runtime test on Windows required, especially if application FastCGI ownership check fails due to unlisted sockets.
