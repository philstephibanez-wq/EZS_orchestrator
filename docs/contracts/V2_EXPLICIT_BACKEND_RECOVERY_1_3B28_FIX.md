# v1.3b28 — correctif bloquant syntaxe récupération

Le commit v1.3b27 a inséré du code au milieu d'une chaîne PowerShell puis dupliqué la fin du fichier, provoquant l'échec de tous les appels `start`, `stop`, `status` et `recover`. v1.3b28 reconstruit le script depuis la version saine v1.3b26 et ajoute la seule branche de récupération à l'emplacement correct. Le test contractuel délimite cette branche entre `recover` et `status`, sans inclure les vrais démarrages/arrêts du script. `recover` n'est pas automatique et conserve les vérifications PID, binaire, commande, TCP, Caddy, HTTP et confirmation. Aucun service n'est modifié par un git pull. Priorité de recette MAIN : parser PowerShell par `[System.Management.Automation.Language.Parser]::ParseFile`, puis test PHP, puis status. Ne pas exécuter une récupération si le parseur rapporte des erreurs.
